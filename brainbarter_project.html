Project Overview — What is BrainBarter?
BrainBarter is a student-powered knowledge marketplace built on a token economy: students earn tokens by uploading high-quality study material (videos and notes), and spend tokens to unlock content created by their peers. Creators can withdraw accumulated earnings directly to a UPI or bank account. Layered on top of this economy is a Retrieval-Augmented Generation (RAG) AI tutor — powered by Google Gemini — that reads the actual uploaded PDFs and answers student doubts with citations to the exact passages it used, rather than generating answers from general knowledge.
🎓
For Learners

Browse and discover content by subject, topic, type, and difficulty. Unlock material using tokens, rate content, bookmark topics, and track progress. Start with 50 free tokens on signup.

🎥
For Creators

Upload videos or PDF notes with subject and topic tags. Earn tokens every time someone unlocks your content. Manage uploads through a creator dashboard. Withdraw earnings to real money.

🤖
AI Study Assistant

RAG-powered doubt solver, summarizer, note generator, and practice question engine — all grounded in the student's own uploaded material with inline citations to source passages.

🛡️
Secure by Design

HMAC-SHA256 payment verification, atomic SECURITY DEFINER DB functions, Row-Level Security on every table, and cryptographic email OTPs — clients cannot manipulate token balances.

RAG Pipeline — How the AI answers from your own material
💡 Standard AI chatbots answer from training data — BrainBarter's AI answers exclusively from the student's uploaded PDF, making every answer verifiable and grounded in the actual syllabus material.

Ingestion Phase (run once after upload)

Step 1
Download PDF from Supabase Storage
Step 2
Extract text via pdf-parse
Step 3
Chunk into ~220-word windows (40-word overlap)
Step 4
Embed each chunk — Gemini text-embedding-004 → 768 floats
Step 5
Store vectors in content_chunks (pgvector)

Retrieval Phase (on every doubt question)

Step 1
Embed student's question (same model)
Step 2
Cosine-similarity search — top 6 chunks for that document
Step 3
Feed numbered passages [1]…[6] to Gemini
Step 4
Return grounded answer + citations array to client
// server/utils/embeddings.js — chunking with overlap
function chunkText(text, size = 220, overlap = 40) {
  const words = text.replace(/\s+/g, ' ').trim().split(' ')
  const chunks = []
  for (let i = 0; i < words.length; i += size - overlap) {
    chunks.push(words.slice(i, i + size).join(' ').trim())
    if (i + size >= words.length) break
  }
  return chunks
}

// server/controllers/aiController.js — semantic retrieval for doubts
const queryEmbedding = await embedText(userMessage)
const { data: matches } = await supabase.rpc('match_content_chunks', {
  p_content_id: contentId,
  query_embedding: queryEmbedding,
  match_count: 6,
})
contentText = matches.map((m, i) => `[${i+1}] ${m.chunk_text}`).join('\n\n')
citations = matches.map((m, i) => ({ ref: i+1, snippet: m.chunk_text.slice(0,180), similarity: m.similarity }))

Security & Engineering Highlights
Implementation What it does & why it matters
HMAC-SHA256 Payment Verification Every Razorpay callback is verified server-side by recomputing the HMAC signature. A client that forges a payment ID cannot credit tokens.
Idempotent Token Crediting credit_purchase() is a SECURITY DEFINER function that checks UNIQUE(payment_id) before crediting — a retried or duplicated webhook callback can never double-credit tokens.
Row-Level Security (RLS) Enabled on every table. The profiles policy explicitly blocks clients from updating token_balance or role — even with a valid JWT. All balance changes go through audited RPCs.
Atomic Withdrawal RPC request_withdrawal() deducts the token balance and inserts the withdrawal record atomically in one DB transaction, preventing double-spend from concurrent requests.
Self-Rating Prevention rate_content() SECURITY DEFINER function checks creator_id ≠ rater_id at the DB level — a creator cannot earn the +2 token rating reward on their own content.
Cryptographic Email OTPs 6-digit codes generated via crypto.randomInt() (CSPRNG), stored in Supabase (not in-memory), expire in 10 minutes, and are deleted on successful use — resilient to cold-start restarts.
Creator-Only Ingestion Guard The /api/ai/ingest route verifies content.creator_id === req.user.id before running the embedding pipeline — preventing anyone from triggering costly GPU work on another user's content.
First-Rating Idempotency The +2 token reward for rating is gated by a DB check for an existing rating row — submitting the same rating twice never double-credits the rater.

AI Features — Full capability overview
🔍
RAG Doubt Solver

Ask any question about an uploaded PDF. The AI retrieves the most relevant chunks via cosine similarity and answers exclusively from those passages, citing [1], [2]… inline. Displayed with a "Grounded in this material" citation panel.

📝
Summarize & Simplify

Condenses any uploaded content into 5–7 bullet points, or re-explains it in plain language. Runs against the full indexed text of the document (not just the title/description).

📋
Generate Notes & Questions

Produces structured revision notes with headings and definitions, plus 10 exam questions (short + long answer) derived directly from the uploaded material.

⚡
Exam Mode (4 modes)

Expected Questions — probable exam questions using PYQ context. Mock Test — 10-question MCQ with answers. Revision Sheet — one-page concept summary. Final Prep — must-revise checklist.

📅
AI Study Planner (Agentic)

Given a subject, optional topic, and target days (3–30), Gemini generates a day-by-day revision plan with daily goals, subtopics, activities (reading, practice, flashcards), and a daily self-check question. Progressive difficulty across the plan.

🏛️
Previous Year Question Context

Exam Mode pulls stored PYQ text dumps from the database and feeds them as additional context to Gemini — so expected questions are calibrated to actual exam patterns, not generic guesses.

Token Economy — The two-sided marketplace model
💰 Token Rules
Buy rate₹1 = 10 tokens
Sell / withdraw rate10 tokens = ₹0.80
Platform fee20% on withdrawals
Minimum purchase₹10 (100 tokens)
Minimum withdrawal₹50 (625 tokens)
Signup bonus50 free tokens
First-rating reward+2 tokens
  • Earn: Upload content → receive tokens every time a learner unlocks it
  • Spend: Unlock any content with tokens via atomic server-side transaction
  • Withdraw: Submit UPI or bank details → admin approves → real INR transferred
  • Buy: Top up via Razorpay — ₹10 minimum, verified server-side
  • Reject refund: If admin rejects a withdrawal, tokens are automatically refunded via refund_tokens() SECURITY DEFINER function
  • Full ledger: Every earn, spend, buy, and withdrawal is recorded with timestamp and type in a transaction history table

08
Authentication & Accounts
  • ✉️ Email-verified signup — 6-digit OTP generated via crypto.randomInt(), sent through SendGrid, stored in Supabase with 10-minute TTL. Codes are deleted on successful verification. Resistant to cold-start restarts (no in-memory state).
  • 🔑 Password reset via email — same OTP flow. User receives a code, enters it to confirm identity, then sets a new password via the Supabase Auth API.
  • 🏷️ Role-based access — roles are user or admin. The admin role is set in the database and propagated through JWT claims. RLS policies and API guards check this role at every sensitive operation.
  • 🎁 50 starter tokens on signup — a PostgreSQL trigger (handle_new_user()) fires on auth.users insert and credits 50 tokens to the new profile automatically.
